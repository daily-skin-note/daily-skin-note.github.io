# 肌管理

肌の状態・使ったスキンケア・生活習慣を毎日記録して、あとから「何をしたとき肌がよかったか」を見返すための、個人用のWebアプリです。

- サーバーなし。`index.html` 1ファイルで動きます（フレームワーク・ビルドなし）
- スマホで使う前提です（幅375pxで設計。PCでも開けます）
- 医療機器ではありません。表示する内容は一般的な目安です。ひどい荒れ・痛み・長引く不調があるときは皮膚科で診てもらってください

## 記録できること

すべて任意です。押さなければ空のまま保存できます。

| 区分 | 項目 |
|---|---|
| 肌の調子 | 総合スコア（5段階）／状態タグ／部位メモ |
| スキンケア | 使った用品（登録済みから選ぶ） |
| 生活 | 寝た時刻・起きた時刻／水分／お通じ／お風呂／メイク／その他（飲酒・ストレスなど） |
| 食事 | 10品目チェック（さ・あ・に・ぎ・や・か・い・た・だ・く）／食べ始め・食べ終わりの時刻 |
| からだ | 体重／生理の開始日・終了日 |
| 写真 | 顔写真（すっぴん × 正面・左・右）。アプリ内のカメラで、顔の枠に合わせて撮れます |
| メモ | 自由メモ |

スキンケア用品には、商品写真と成分を登録できます。成分表の文字を貼りつけると、あてはまる成分を自動でチェックします。

## 見返し

- **カレンダー** … 肌スコアを色の濃淡で表示。マスをタップでその日の記録を開く
- **グラフ** … 肌スコア・睡眠・生理期間／体重／食事の品目数／寝る・起きる時刻／食べていない時間（16時間ダイエット用）／条件ごとの平均スコア
- **アイテム** … いまの肌におすすめの成分／アイテム別・成分別の「使った日の平均スコア」

## データの保存先

記録は、使っているブラウザの中に保存されます。外部のサーバーには送りません。

| もの | 保存先 |
|---|---|
| 記録・アイテム・生理日 | ブラウザの localStorage |
| 写真 | ブラウザの IndexedDB（保存前に長辺800px・JPEGに縮小） |

**ブラウザのデータを消すと、記録も消えます。** 次の2つでバックアップできます。

- **JSON書き出し／読み込み**（設定）… 記録をファイルにして保管・端末の移行ができます（写真は含まれません）
- **Google Drive**（設定・任意）… 自分の Google Drive の「アプリ専用フォルダ」に、記録と写真を保存・復元します
  - このアプリが作ったファイルだけを読み書きします（権限は `drive.appdata` のみ）。ほかのアプリや通常の Drive 画面からは見えません
  - 「写真も Drive に送る」をオフにすると、写真は端末の中だけに残ります
  - ログインが切れているときは、カレンダー上部に「Drive への保存が止まっています」と出ます

## 使い方

1. 公開ページをブラウザで開きます（カメラは https のページでだけ使えます）
2. 「今日を記録する」から記録します。保存ボタンを押したときに保存されます
3. ときどき、設定から JSON を書き出すか、Google Drive に保存します。書き出しから30日たつと、カレンダーの上に声かけが出ます

## Google Drive 連携を自分の環境で使うには

`index.html` の中の `G_CLIENT_ID` は、このアプリ用に作った OAuth クライアントIDです。別の場所に置いて使う場合は、自分で用意して差し替えてください。

1. Google Cloud でプロジェクトを作り、Google Drive API を有効にします
2. OAuth 同意画面を設定し、権限に `https://www.googleapis.com/auth/drive.appdata` だけを追加します。公開状態が「テスト」の間は、自分のアカウントをテストユーザーに追加します
3. クライアントID（種類は「ウェブ アプリケーション」）を作り、「承認済みの JavaScript 生成元」に、公開ページのアドレス（例: `https://<ユーザー名>.github.io`。パスや末尾の `/` は付けない）を入れます
4. `index.html` の `G_CLIENT_ID` を、作ったIDに書き換えます

クライアントIDは公開されても問題のない番号です。クライアントシークレットは使いません。

## 作りの方針

- 1ファイル完結。オフラインでも動く（Google ログインを除く）
- グラフは外部ライブラリなしで SVG を手で描く
- 日付は `YYYY-MM-DD` の文字列で持つ（タイムゾーンのズレを避けるため）
- データに `version` を持ち、読み込み時に古い形を変換する
- Apple のヒューマンインターフェイスガイドラインに沿って設計（タップ領域44pt以上、下のタブバー、ダークモード対応、動きを減らす設定の尊重など）
